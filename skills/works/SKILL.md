# works — 프로젝트 작업 시작 워크플로우

## 이 스킬이 해결하는 것

작업을 시작할 때마다 매번 같은 것을 다시 찾는다. 이 과제가 SSOT 어디에 있는지,
작업공간이 있는지, 지난번에 어디까지 했는지, 무엇을 원본으로 봐야 하는지.
**그 반복을 인터뷰 7문으로 끝내고 지시 가능한 상태까지 세팅한다.**

산출물은 세팅된 작업 환경 + 복귀 브리핑 + 작업지시문 1장이다.

## 도구

**세션에서 한 번, 환경을 먼저 확인한다.** OS 도 경로도 사람마다 다르다.

macOS:

```bash
uname -s; ls ~/{{WORKSPACE_NAME}}/scripts/works.py 2>/dev/null || ls ~/.claude/skills/works/works.py
python3 -V || python -V
```

Windows (PowerShell):

```powershell
Get-ChildItem "$env:USERPROFILE\.claude\skills\works\works.py" -ErrorAction SilentlyContinue
python -V; py -V
```

- 스크립트가 `~/{{WORKSPACE_NAME}}/scripts/` 에 있으면 연구기획사업부 담당자 맥이다 (정본)
- `.claude/skills/works/` 에 있으면 부서원 PC 다 (배포 사본)
- 스크립트가 없으면 >> 아래 §설치
- **파이썬이 없으면** >> 아래 §파이썬 없이 쓰기 (설치를 강요하지 않는다)

확인된 스크립트 경로를 `<W>`, 파이썬 실행기를 `<PY>`(`python3` · `python` · `py` 중 되는 것)로 둔다.

```
<PY> <W> list                     # SSOT 과제 목록 + 작업공간 연결 여부
<PY> <W> brief <키워드>            # 복귀 브리핑
<PY> <W> bootstrap <키워드>        # 진입점 CLAUDE.md 를 실제 상태로 채워 생성
<PY> <W> desktop <키워드>          # Claude Desktop 세팅 묶음
<PY> <W> open <slug> --title "<과제명>"    # 작업 폴더 준비 (+ 설정된 작업창)
<PY> <W 와 같은 폴더>/new-project.py <slug> "<과제명>" --category <경로>   # 신규 개설
```

SSOT 경로는 스크립트가 OS 에 맞게 자동으로 찾는다 — macOS 는 `~/Library/CloudStorage/GoogleDrive-<계정>/`,
Windows 는 드라이브 문자(`G:\공유 드라이브\`)와 `%USERPROFILE%\Google Drive\`. 폴더명은
`공유 드라이브` · `Shared drives` 둘 다 본다. 못 찾으면 스크립트가 OS 별로 확인할 것을 알려준다.

## 설치

설치가 안 된 사람에게는 **SSOT `50_도구상자/10_스킬/설치.md` 를 안내한다.**
그 파일 내용을 Claude Code 대화창에 붙여넣으면 환경을 확인해 알아서 설치한다 —
경로·OS·드라이브 문자를 사람이 알 필요가 없다.

명령을 직접 붙여넣게 하지 않는다. 윈도우 실행 정책과 경로 오타에 걸리기 쉽다.

복사되는 것은 이 스킬 폴더 전체이고 `works.py` · `works_env.py` · `new-project.py` 가 함께 들어온다.
설치 후 Claude Code 를 완전히 종료하고 다시 실행해야 `/works` 가 잡힌다 (세션 시작 때 읽는다).
`~/{{WORKSPACE_NAME}}` 작업공간은 **없어도 된다** — 없으면 해당 기능만 건너뛴다.

## 파이썬 없이 쓰기

Windows 에는 파이썬이 기본으로 없다. **설치를 요구하지 말고, 이 스킬이 직접 한다.**
스크립트가 하는 일을 파일 도구(Glob·Read·Grep)로 대신한다. 결과는 같고 조금 느리다.

| 스크립트 | 파이썬 없이 |
|---|---|
| `list` | SSOT `{{DEPT_ROOT}}/10_과제/` 아래 4개 분류 폴더를 각각 나열한다 |
| `brief` | 과제 폴더에서 `CLAUDE.md` · `_README.md` · `★기준본*` · `_인계노트*` · `_WORKER_LOG*` 를 찾아 읽고, 하위 폴더를 나열해 최근 수정된 것부터 5건을 고른다 |
| `bootstrap` | 위에서 읽은 내용으로 `CLAUDE.md` 본문을 직접 써서 사용자에게 보여주고, 승인받아 과제 폴더에 만든다 |
| `desktop` | 프로젝트 이름·지침·첨부 목록을 직접 작성해 전달한다 |

**SSOT 경로를 먼저 찾아야 한다.** Windows 에서 파일 도구로 다음 순서로 확인한다:
`G:\공유 드라이브\{{SSOT_DRIVE}}` >> 다른 드라이브 문자 >> `%USERPROFILE%\Google Drive\...`.
찾은 경로를 세션 안에서 계속 쓰고, 사용자에게 한 번 확인받는다.

파이썬이 있으면 항상 스크립트를 쓴다 — 사람마다 결과가 달라지지 않는다.

## 절차

**한 번에 여러 질문을 몰아 묻지 않는다.** 한 단계씩 묻고, 답을 받은 뒤 다음으로 넘어간다.
답에서 이미 확정된 것은 다시 묻지 않는다.

### 0단계. 어느 환경인가

**이것을 가장 먼저 묻는다.** 뒤 단계가 전부 갈린다.

AskUserQuestion 으로 두 갈래를 제시한다.

| 선택 | 무엇 | 어디로 |
|---|---|---|
| **터미널 / 데스크탑 앱 (Claude Code)** | 셸을 쓸 수 있다. 폴더 생성·워크스페이스 기동이 자동 | **A 경로** — 1단계로 |
| **Claude Desktop 앱** | 셸이 없다. 세팅은 사람이 앱에서 한다 | **B 경로** — 아래 |

Claude Code 는 터미널이든 데스크탑 앱이든 같은 A 경로다. 셸이 있는지가 기준이다.
지금 세션이 Claude Code 라면 B 를 고른 사용자는 **다른 사람(직원)을 위한 세팅**을 만드는 것이다.

**A 경로를 고르면 곧바로 §도구의 환경 확인을 실행한다.** OS(macOS·Windows) 와 파이썬 유무를
사람에게 묻지 않는다 — 명령 한 번으로 알 수 있는 것을 질문으로 늘리지 않는다.

**B 경로를 고르면**: 1단계·2단계(신규/기존 · 어느 과제)는 그대로 묻고, 3단계부터 이렇게 한다.

```bash
<PY> <W> desktop "<과제 키워드>"
```

프로젝트 이름 · 붙여넣을 지침 · 첨부할 기준문서 목록이 나온다. 그것을 사용자에게 그대로 전하고,
앱에서 해야 할 세 가지(프로젝트 만들기 · 지침 붙여넣기 · 파일 첨부)를 안내한다.
그 뒤 5단계(업무 1건 + AX 판정)·6단계(작업지시문)는 A 와 똑같이 진행한다.
신규 과제인데 SSOT 폴더가 없으면 4단계의 `new-project.py` 를 먼저 돌려 폴더를 만든다
(이건 셸이 있는 이 세션에서 대신 해줄 수 있다).

### 1단계. 신규인가 기존인가

AskUserQuestion 으로 묻는다. 선택지는 둘이다.

- **기존 과제 이어서** — SSOT에 폴더가 이미 있다
- **신규 과제 개설** — 이번에 처음 만든다

판단이 서면 묻지 않고 넘어간다. 사용자가 `/works 자폐` 처럼 과제를 함께 준 경우,
`works.py list` 로 존재를 확인하고 바로 2단계를 건너뛴다.

### 2단계. 어느 과제인가

**기존이면**: `works.py list` 를 실행해 결과를 보여주고 번호나 이름으로 받는다.
분류 4개(`1_수행중` · `2_실주` · `3_종료·정산` · `4_인증·기타`)가 함께 나오므로
사용자가 분류부터 좁혀 말하면 그 안에서만 제시한다.

**신규이면** 세 가지를 받는다.

| 무엇 | 예 | 규칙 |
|---|---|---|
| SSOT 과제 폴더명 | `복지분야 AX-SPRINT (청년고립 예방)` | 사업의 공식 명칭 + 괄호에 식별어. 기존 8건의 작명을 따른다 |
| 분류 | `1_수행중` | 협약 전이면 `2_실주` |
| slug | `ax-sprint` | 영문 kebab-case. 작업공간 폴더명이 된다 |

### 3단계. 복귀 브리핑 (기존만)

```bash
<PY> <W> brief "<과제 키워드>"
```

GOAL의 「지금 상태」 · 태스크 원장 행 · 최근 작업 로그 · SSOT 최근 변경 · 최근 관련 메일이
한 번에 나온다. **이것을 그대로 붙여넣지 말고 읽은 뒤 3~5줄로 요약해서 보고한다.**

요약에 반드시 넣을 것:
- 마지막 세션이 어디서 멈췄는지 (인계 문서가 있으면 그 경로)
- 그 뒤에 새로 들어온 것 (메일·SSOT 변경 중 마지막 로그 이후 날짜인 것)
- 지금 걸려 있는 마감

브리핑에 `작업공간: **없음**` 이 나오면 4단계에서 작업공간부터 만든다.

### 4단계. 환경 세팅

**신규 또는 작업공간 없는 기존**:

```bash
<PY> <W 와 같은 폴더>/new-project.py <slug> "<과제 폴더명>" \
    --category "{{DEPT_ROOT}}/10_과제/<분류>" --dry-run
```

`--dry-run` 으로 만들 것을 먼저 보여주고 승인받은 뒤 실제 실행한다.
기존 파일은 덮어쓰지 않으므로 **이미 있는 과제에 다시 돌려도 안전하다** —
빠진 파일만 생기므로, 브리핑에 `⚠ 진입점 없음` 이 뜬 과제를 고칠 때도 이 명령을 쓴다.

한 번에 생기는 것:

| 어디 | 무엇 |
|---|---|
| 작업공간 | `GOAL.md` · `RULES.md` · **`CLAUDE.md`(세션 진입점)** · `.claude/settings.local.json` |
| SSOT 과제 폴더 | `00_기준문서/` · `수행/` · `_README.md`(사람용) · **`CLAUDE.md`(폴더 부트스트랩)** |

`CLAUDE.md` 두 개가 진입점이다. 작업공간용은 세션을 열면 읽히고, SSOT용은 그 폴더를
컨텍스트로 열었을 때 읽힌다. **B 경로(Desktop)에서는 SSOT 쪽 `CLAUDE.md` 가
프로젝트 지침을 대신할 수 있다** — 폴더를 붙이면 규칙이 함께 따라온다.

**이미 자료가 쌓인 기존 과제라면 `new-project.py` 대신 이것을 쓴다:**

```bash
<PY> <W> bootstrap "<과제 키워드>"           # 미리보기
<PY> <W> bootstrap "<과제 키워드>" --apply   # 생성
```

`new-project.py` 는 빈칸 템플릿을 주고, `bootstrap` 은 **그 과제의 실제 상태로 채운다** —
먼저 읽을 문서(`★기준본`·`_인계노트`·`_WORKER_LOG` 자동 탐지) · 하위 폴더 구성 ·
최근 변경 · 작업 로그 · GOAL 「지금 상태」. 미리보기로 본문을 먼저 보여주고 승인받는다.
기존 `CLAUDE.md` 는 덮어쓰지 않는다.

빈칸 진입점은 결국 사람이 다시 채워야 하므로, 자료가 있는 과제에는 항상 `bootstrap` 을 쓴다.

**워크스페이스 기동** (사용자가 새 창에서 작업하려는 경우만):

```bash
<PY> <W> open <slug> --title "<과제명>"
```

설정한 작업창이 열린다 (`workspace.open_command`). 설정하지 않았으면 열 폴더를 알려 준다.
이미 이 세션에서 작업할 것이라면 기동하지 않고 `cd` 만 한다 — 세션을 중복으로 띄우지 않는다.

**작업창 열기는 선택이다.** 설정하지 않았으면 사용자가 그 폴더에서
새 Claude Code 세션을 열도록 안내한다 (또는 `/add-dir` 로 SSOT 과제 폴더를 지금 세션에 붙인다).

### 5단계. 이번 세션의 업무 1건과 AX 판정

무엇을 처리할지 한 줄로 받는다.

**받자마자 그 업무의 기존 산출물을 찾는다. 이것을 건너뛰지 않는다.**
브리핑의 「SSOT 폴더 구성」에서 그 업무에 해당하는 폴더를 열고 실제 파일을 본다.

파일 도구(Glob)로 그 폴더를 훑는다 — OS 와 무관하게 동작한다.
셸을 쓸 경우 macOS 는 `ls -R … | head -30`, Windows 는 `Get-ChildItem … -Recurse | Select-Object -First 30`.

- 이미 있으면 **최신 버전과 그 상태를 사용자에게 먼저 알린다.** 업무를 재정의할지 묻는다
- `★기준본` · `_인계노트` · `_WORKER_LOG` 로 시작하는 파일이 있으면 먼저 읽는다.
  그 안에 이미 확인된 사실이 있어 다시 조사할 필요가 없다
- 브리핑의 「최근 변경」은 5건만 보여준다. 몇 달 전 산출물은 걸리지 않으므로
  **최근 변경에 없다는 것이 없다는 뜻이 아니다**

실측 사례(2026-09-07): NIPA 과제에서 「중간점검 보고서 작성」을 업무로 골랐으나
`20_중간보고서/` 에 이미 v3.1 수정대장까지 있었다. 확인하지 않았으면 있는 것을 다시 만들었다.

그 다음 `AX_Workflow` §1 판정을 적용한다.

| | 결과를 검증할 수 있다 | 검증할 수 없다 |
|---|---|---|
| **기준을 글로 쓸 수 있다** | **지금 한다** | 검증 방법을 먼저 만든다 |
| **글로 쓸 수 없다** | 기준을 글로 쓰는 것부터 한다 | **사람이 한다.** AX 대상이 아니다 |

오른쪽 아래에 걸리면 그렇다고 말하고, AI에 넘기지 말고 사람이 할 일로 정리한다.
이 판정을 건너뛰지 않는다. 도구부터 주는 것이 실패의 첫 번째 이유다.

### 6단계. 작업지시문 4요소 확정

빈칸을 채워 사용자에게 확인받는다. 넷이 다 차면 지시, 하나라도 비면 질문이다.

```
[무엇을] <업무> 를 처리한다
[원본]   <경로> (읽기 전용, 수정 금지)
[규칙]   <지킬 것 2~3개> / <하지 말 것 1~2개>
[산출물] <경로/파일명>
[검증]   <어떻게 확인하면 되는지 1줄>
```

### 산출물은 전부 SSOT 과제 폴더에 둔다 (운영자 확정 2026-09-29)

> 「다음부터는 **무조건 SSOT 에 폴더를 생성해 거기에 모든 데이터를 넣어라.
> 이제 내 작업 폴더는 없다고 생각해야 한다.** 그래야 다 함께 협업이 가능하다.」

초안·중간 산출물·조사 자료·발주문·실행로그·작업지시문까지 **전부 SSOT 과제 폴더 안**이다.
혼자 보는 임시 파일도 예외가 아니다.

| 환경 | 어디에 |
|---|---|
| **A (Claude Code)** | **SSOT 과제 폴더.** 작업공간(`~/{{WORKSPACE_NAME}}/projects/<slug>/`)에는 캐시·재생성 가능한 것만 |
| **B (Claude Desktop)** | 대화에서 만들고, **사람이 확인한 뒤 SSOT 과제 폴더에** 올린다 |

**왜**: `~/{{WORKSPACE_NAME}}/projects/` 는 담당자 맥에만 있다. 거기 쌓인 것은 부서원이 볼 수 없어
인계가 끊기고 같은 조사를 다시 하게 된다. SSOT 가 부서 전원이 접근하는 유일한 공간이다.

**마운트가 지연돼 SSOT 폴더가 안 보이면 기다리지 말고 `SSOT_rw:` API 로 쓴다.**
쓴 뒤에는 `SSOT_ro:` 로 클라우드 도착을 확인하고 나서 완료를 보고한다.

확인이 끝나면 세팅 완료를 알리고 작업에 들어간다.

## 세션을 닫을 때

작업이 끝나면 다음 사람(또는 다음 세션의 나)이 3단계 브리핑만 보고 이어갈 수 있어야 한다.

**작업공간이 있는 맥 (연구기획사업부)**

1. `GOAL.md` 「지금 상태」 갱신 — 여기가 브리핑의 첫 소스다
2. `~/{{WORKSPACE_NAME}}/logs/YYYY-MM-DD_<주제>.md` 기록 (지시 / 결과 / 산출물 / 결정 / 다음)
3. `~/{{WORKSPACE_NAME}}/TASKS.md` 행 갱신
4. 확정본이 생겼으면 SSOT로 올리고 과제 폴더 `_README.md` 갱신
5. AI가 틀린 것이 있었으면 **실수 1건 = 규칙 1줄** 로 `RULES.md` 나 공통 오답노트에 추가

**작업공간이 없는 맥 (부서원)**

1. SSOT 과제 폴더의 `CLAUDE.md` 「지금 급한 것」을 갱신한다 — 다음 세션이 이것부터 읽는다
2. 확정본이 생겼으면 사람이 확인한 뒤 과제 폴더에 올린다. 초안은 올리지 않는다
3. AI가 틀렸으면 그 실수를 규칙 1줄로 그 `CLAUDE.md` 에 추가한다
4. 로그·태스크 원장 갱신은 연구기획사업부에 알린다 (그쪽 저장소에 있다)

## 지키는 것

- SSOT·U드라이브 원천은 **읽기 전용**. 확정본 올리기 외의 쓰기는 하지 않는다
- 발송(메일·봇)은 승인된 유형만. 신규 유형은 운영자 승인 후
- 태스크 상태는 `rpbd-infra/scripts/tasks/apply.py` 로 바꾼다. 원장을 직접 고치지 않는다
- 규범 전문은 SSOT `50_도구상자/00_규범/` 5건
