# 프로젝트 작업 워크플로우 — `works`

> 과제 작업을 시작할 때마다 반복되는 세팅을 **인터뷰 7문**으로 끝내고,
> 지시 가능한 상태까지 만들어 주는 절차입니다.

## 왜 필요한가

작업을 시작할 때마다 같은 것을 다시 찾습니다. 이 과제가 SSOT 어디에 있는지, 지난번에
어디까지 했는지, 무엇을 원본으로 봐야 하는지, 결과를 어디에 남겨야 하는지.

찾는 데 드는 시간이 문제의 절반이고, **못 찾아서 새로 만드는 것**이 나머지 절반입니다.
같은 자료가 여러 벌 생기는 이유가 여기 있습니다.

현재 상태(2026-09-07 실측): SSOT 과제 30건 중 작업공간이 연결된 것은 **2건**입니다.
나머지 28건은 작업을 시작할 때마다 맨손으로 시작하고 있습니다.

## 무엇을 하는가

```
/works  >>  ⓪ 어느 환경  >>  ① 신규/기존  >>  ② 어느 과제  >>  ③ 복귀 브리핑
        >>  ④ 환경 세팅  >>  ⑤ 업무 1건 + AX 판정  >>  ⑥ 작업지시문 확정  >>  작업 시작
```

⓪이 먼저입니다. 셸을 쓸 수 있는 환경(Claude Code)인지, Claude Desktop 앱인지에 따라
④ 세팅 방식이 갈립니다. 나머지 질문은 두 환경에서 같습니다.

산출물은 세 가지입니다.

| 산출물 | 무엇 |
|---|---|
| 세팅된 작업 환경 | 작업공간 + SSOT 과제 폴더 연결 |
| 복귀 브리핑 | 지난 세션이 어디서 멈췄는지, 그 뒤 무엇이 들어왔는지 |
| 작업지시문 1장 | 4요소(원본·규칙·산출물·검증)가 채워진 지시문 |

## 7문 인터뷰

### ⓪ 어느 환경인가

| 환경 | 세팅 방식 |
|---|---|
| **Claude Code** (터미널 또는 데스크탑 앱) | 자동. 폴더 생성·워크스페이스 기동까지 됩니다 |
| **Claude Desktop 앱** | 붙여넣을 지침을 만들어 드리고, 앱에서 사람이 3단계로 세팅합니다 |

Claude Code는 터미널이든 데스크탑 앱이든 같습니다. 셸을 쓸 수 있는지가 기준입니다.

### ① 신규인가 기존인가

기존은 SSOT에 폴더가 이미 있는 과제, 신규는 이번에 처음 만드는 과제입니다.

### ② 어느 과제인가

기존이면 목록에서 고릅니다. 분류가 4개입니다.

| 분류 | 무엇 |
|---|---|
| `1_수행중` | 협약 체결하고 수행 중 (8건) |
| `2_실주` | 신청·선정 대기 또는 미선정 (14건) |
| `3_종료·정산` | 과제 종료 후 정산·사후관리 (5건) |
| `4_인증·기타` | 인증·특허·지정 (3건) |

신규면 세 가지를 정합니다.

| 무엇 | 예 | 규칙 |
|---|---|---|
| SSOT 과제 폴더명 | `복지분야 AX-SPRINT (청년고립 예방)` | 공식 사업명 + 괄호에 식별어 |
| 분류 | `1_수행중` | 협약 전이면 `2_실주` |
| 작업공간 이름(slug) | `ax-sprint` | 영문 소문자·하이픈 |

### ③ 복귀 브리핑 (기존만)

다섯 곳을 한 번에 읽어서 보여줍니다.

| 소스 | 무엇을 알려주나 |
|---|---|
| 작업공간 `GOAL.md` 「지금 상태」 | 지난 세션이 어디서 멈췄는지 |
| `TASKS.md` | 이 과제로 등록된 작업 ID와 상태 |
| 최근 작업 로그 | 무엇을 했는지 (파일 경로) |
| SSOT 과제 폴더 최근 변경 | 확정본이 언제 바뀌었는지 |
| 최근 관련 메일 | 마지막 작업 이후 새로 들어온 것 |

**이 절이 이 워크플로우의 핵심입니다.** 사람이 기억으로 복귀하지 않게 만드는 것이
목적이고, 그래서 새로 입력을 요구하지 않습니다. 이미 남아 있는 것만 모읍니다.

### ④ 환경 세팅

작업공간이 없으면 만듭니다. 한 번에 다음이 생깁니다.

| 어디 | 무엇 |
|---|---|
| 작업공간 `~/{{WORKSPACE_NAME}}/projects/<slug>/` | `GOAL.md`(목표·지금 상태) · `RULES.md`(과제 규칙) · **`CLAUDE.md`(세션 진입점)** |
| SSOT 과제 폴더 | `00_기준문서/` · `수행/` · `_README.md`(사람용 안내) · **`CLAUDE.md`(폴더 부트스트랩)** |
| 연결 설정 | 이 작업공간에서 세션을 열면 SSOT 과제 폴더가 항상 함께 보입니다 |

**`CLAUDE.md` 두 개가 진입점입니다.** AI가 그 폴더에서 일을 시작할 때 무엇부터 읽어야 하는지,
무엇을 하면 안 되는지가 적혀 있습니다. 이것이 없으면 매번 사람이 같은 설명을 반복해야 합니다.

이미 자료가 쌓인 기존 과제는 **빈칸 대신 실제 상태로 채워서** 만듭니다.

| 무엇이 채워지나 | 어디서 가져오나 |
|---|---|
| 먼저 읽을 문서 | `★기준본` · `_인계노트` · `_WORKER_LOG` 로 시작하는 파일을 자동으로 찾습니다 |
| 이 폴더 구성 | 하위 폴더 목록 |
| 최근 상태 | SSOT 최근 변경 · 작업 로그 · GOAL 「지금 상태」 |

빈칸 진입점은 결국 사람이 다시 채워야 합니다. 그러면 이 워크플로우가 없애려던 반복이 그대로 남습니다.

기존 파일은 절대 덮어쓰지 않습니다. 이미 있는 것은 건너뛰고 보고만 하므로,
**진입점이 빠진 과제에 다시 돌려도 안전합니다** (빠진 것만 생깁니다).

### ⑤ 이번 세션의 업무 1건 + AX 판정

무엇을 처리할지 한 줄로 정합니다.

**그 다음 그 업무의 기존 산출물을 먼저 찾습니다.** 이미 만들어 둔 것이 있는지,
있으면 어느 버전이 최신인지 확인합니다. `★기준본`·`_인계노트`·`_WORKER_LOG`로 시작하는
파일이 있으면 먼저 읽습니다. 그 안에 이미 확인된 사실이 있어 다시 조사하지 않아도 됩니다.

> 실제 사례(2026-09-07): NIPA 과제에서 「중간점검 보고서 작성」을 업무로 골랐는데
> `20_중간보고서/`에 이미 v3.1 수정대장까지 있었습니다. 확인하지 않았으면 있는 것을 다시 만들었습니다.
> **복귀 브리핑의 「최근 변경」은 5건만 보여줍니다. 거기에 없다는 것이 없다는 뜻이 아닙니다.**

그 다음 그것이 AI에 맡길 일인지 판정합니다.

| | 결과를 검증할 수 있다 | 검증할 수 없다 |
|---|---|---|
| **기준을 글로 쓸 수 있다** | **지금 합니다** | 검증 방법을 먼저 만듭니다 |
| **글로 쓸 수 없다** | 기준을 글로 쓰는 것부터 합니다 | **사람이 합니다.** AX 대상이 아닙니다 |

오른쪽 아래에 걸리는 업무를 AI에 넘기면 시간만 쓰고 결과를 못 씁니다.
**이 판정을 건너뛰고 도구부터 주는 것이 AI 도입이 실패하는 첫 번째 이유입니다.**

### ⑥ 작업지시문 4요소

```
[무엇을] <업무> 를 처리한다
[원본]   <경로> (읽기 전용, 수정 금지)
[규칙]   <지킬 것 2~3개> / <하지 말 것 1~2개>
[산출물] <경로/파일명>
[검증]   <어떻게 확인하면 되는지 1줄>
```

넷이 다 차면 지시, 하나라도 비면 질문입니다. 산출물 경로는 환경에 따라 다릅니다.

| 환경 | 초안·작업 | 확정본 |
|---|---|---|
| Claude Code | 임시 스크립트·캐시만 `~/{{WORKSPACE_NAME}}/projects/<slug>/` | **산출물 전부** SSOT 과제 폴더 |
| Claude Desktop | 작업공간 없음 | **산출물 전부** SSOT 과제 폴더 |

산출물은 어느 환경이든 SSOT에 둡니다 (규약 변경 2026-09-21 Roy).
**에이전트 산출물이 로컬에만 남으면 다른 팀원이 이어서 일할 수 없기 때문입니다.**
정본(`수행/_*.md`)과 근거(조사 원본·발주문·실행로그)는 **구분하되 분리하지 않습니다.**

## 환경별 실행 방법

### A. Claude Code (터미널 또는 데스크탑 앱)

```
/works
```

인터뷰가 진행되고 세팅까지 자동으로 됩니다.

**설치는 Claude Code에게 맡깁니다.** 사람이 명령을 붙여넣지 않습니다.

SSOT `50_도구상자/10_스킬/설치.md` 내용을 전부 복사해서 Claude Code 대화창에 붙여넣으면 끝입니다.
경로도 OS도 드라이브 문자도 몰라도 됩니다. Claude Code가 직접 찾아 설치하고 확인까지 하며,
막히면 무엇이 문제인지 알려줍니다.

설치 후 **Claude Code를 완전히 종료하고 다시 실행해야** `/works` 가 나타납니다.
스킬은 세션을 시작할 때 읽습니다.

없어도 되는 것:

| 무엇 | 없으면 |
|---|---|
| 작업공간(`~/{{WORKSPACE_NAME}}`) | 과제 목록·복귀 브리핑·진입점 생성은 그대로 됩니다. 작업공간 관련 절만 비워집니다 |
| **파이썬** | 스킬이 파일 도구로 같은 일을 직접 합니다. 조금 느립니다 |
| cmux | 워크스페이스 자동 기동만 안 됩니다 (macOS 전용 도구입니다) |
| SSOT 경로 설정 | OS에 맞게 자동으로 찾습니다 |

구글 드라이브가 실행 중이고 `공유 드라이브 > {{SSOT_DRIVE}}` 가 보이면 됩니다.
못 찾으면 무엇을 확인할지 알려줍니다.

### 윈도우에서 다른 점

부서원 PC는 전부 윈도우입니다. 절차와 질문은 같고, 다음 세 가지만 다릅니다.

| 무엇 | 윈도우 |
|---|---|
| SSOT 위치 | 드라이브 문자(`G:\공유 드라이브\{{SSOT_DRIVE}}`) 또는 `내 문서`의 `Google Drive` 폴더 |
| 파이썬 | 기본으로 없습니다. **설치하지 않아도 됩니다** — 있으면 쓰고, 없으면 스킬이 직접 합니다 |
| 워크스페이스 자동 기동 | 안 됩니다. 과제 폴더에서 새 세션을 열거나 `/add-dir` 로 붙입니다 |

> **아직 윈도우 실기 검증은 하지 않았습니다** (2026-09-07 기준). 경로 처리와 안내는 윈도우를
> 전제로 작성했지만, 실제 PC에서 한 번 돌려봐야 확정할 수 있습니다. 아래 §검증 대기 참조.

### B. Claude Desktop (직원 · 앱 환경)

Desktop에는 터미널이 없어서 폴더 생성·워크스페이스 기동이 자동으로 되지 않습니다.
**인터뷰와 판정, 작업지시문은 그대로 쓰고 세팅만 방식이 다릅니다.**

세 가지 방식이 있고, 진입 비용 순으로 놓았습니다.

| 방식 | 무엇이 되나 | 설치 부담 | 권고 |
|---|---|---|---|
| **B-1. 프로젝트 + 지침** | 과제별 Project를 만들고 지침에 이 절차와 SSOT 경로를 넣습니다. 기준문서는 지식으로 첨부 | 없음 (지침은 자동 생성) | **여기서 시작** |
| **B-2. + 구글 드라이브 연결** | SSOT를 직접 검색·열람. 첨부를 매번 갱신하지 않아도 됩니다 | 커넥터 연결 1회 | 익숙해지면 |
| **B-3. + 파일 접근 연결** | 읽기에 더해 **쓰기**가 됩니다. A와 절차가 같아집니다 | 커넥터 설치 + 경로 지정 | 검증 후 판단 |

**B-1 하는 방법** (5분)

세팅 묶음은 만들어 드립니다. 연구기획사업부에 과제명을 말하면 다음이 나옵니다.

- 프로젝트 이름 (SSOT 과제 폴더명과 같게)
- **프로젝트 지침 전문** — 정본 경로·읽기전용 원칙·AX 판정·작업지시문 4요소·세션 마감이 들어 있습니다
- 첨부할 기준문서 목록 (그 과제의 공고문·관리기준·`_README.md`)

앱에서 할 일은 세 가지입니다.

1. Project를 하나 만들고 받은 이름을 붙입니다.
2. 프로젝트 지침에 받은 지침을 붙여넣습니다.
3. 목록에 있는 파일을 지식으로 첨부합니다.

과제 폴더에 `CLAUDE.md`(폴더 부트스트랩)가 있으면 그 파일을 첨부하는 것으로
2번을 대신할 수 있습니다. 같은 내용이 들어 있고, 폴더를 쓸 때마다 함께 따라옵니다.

그 뒤 작업을 시작할 때 "works 절차로 시작하자"라고 쓰면 같은 인터뷰가 진행됩니다.

프로젝트 하나가 작업공간 하나에 해당합니다. 지난 대화가 그 프로젝트에 쌓이므로
복귀 브리핑을 사람이 다시 설명하지 않아도 됩니다.

**B-2·B-3 은 검증 후 안내합니다.** 커넥터 종류와 권한 범위를 연구기획사업부가 먼저
한 대에서 확인한 뒤 배포합니다 (아래 §검증 대기).

## 세션을 닫을 때

다음 사람이 복귀 브리핑만 보고 이어갈 수 있어야 합니다.

1. `GOAL.md` 「지금 상태」 갱신 >> 브리핑의 첫 소스입니다
2. 작업 로그 기록 (지시 / 결과 / 산출물 / 결정 / 다음)
3. `TASKS.md` 행 갱신
4. 확정본이 생겼으면 SSOT에 올리고 과제 폴더 `_README.md` 갱신
5. AI가 틀린 것이 있으면 **실수 1건 = 규칙 1줄** 로 규칙에 추가

## 검증 대기 (연구기획사업부)

| 무엇 | 왜 |
|---|---|
| Desktop 커넥터(B-2·B-3) 실기 확인 | 권한 범위와 쓰기 동작을 한 대에서 확인한 뒤 배포 |
