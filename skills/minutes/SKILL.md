# minutes: 회의록 전사와 교정

## 이 스킬이 하는 일

자동 전사는 고유명사와 숫자를 틀린다. **들린 대로 적으면 틀린 이름이 사실처럼 굳는다.**
그래서 이 스킬은 전사에서 끝내지 않고 **회사 정본으로 교정하는 단계까지** 간다.

```
전사 확보  >>  용어 교정  >>  1차 브리핑  >>  사람이 수정  >>  확정본
(Fathom 또는 로컬 Whisper)   (온톨로지·과제 맥락)      (오답노트)
```

---

## 0단계. 어느 경로인가

**먼저 묻는다. 답에 따라 전부 갈린다.**

| 선택 | 언제 | 어디로 |
|---|---|---|
| **온라인 회의** (Zoom, Google Meet) | Fathom이 자동 녹화했다 | A 경로 |
| **녹음 파일** (m4a, mp3, wav 등) | 대면 회의를 휴대폰 등으로 녹음했다 | B 경로 |

사용자가 파일 경로를 이미 줬으면 묻지 말고 B로 간다.

---

## A 경로. Fathom 전사

### A-1. Fathom 준비 (각자 본인 계정으로 한 번만)

Fathom 은 온라인 회의에 참석해 자동으로 녹화하고 전사하는 도구다.
**각자 본인 계정으로 가입하고 본인 MCP 를 연결한다.** 남의 계정을 공유하지 않는다.

1. `fathom.video` 에서 **회사 이메일로** 가입한다 (무료 플랜으로 충분하다)
2. Zoom 또는 Google Meet 계정을 연결한다
3. Claude Code 에 본인 Fathom 을 붙인다. 터미널에서 한 번만 실행한다

```bash
claude mcp add fathom -- env -u NODE_OPTIONS npx -y mcp-remote@latest https://api.fathom.ai/mcp
```

4. Claude Code 를 다시 켜면 브라우저가 열린다. **본인 Fathom 계정으로 로그인**하면 끝이다
   API 키를 파일로 저장할 필요가 없다. 인증은 브라우저에서 한 번만 한다

연결을 확인한다.

```bash
claude mcp list
```

`fathom` 이 `connected` 로 나오면 된다. 실패하면 Claude Code 를 완전히 종료했다 다시 켠다.

연결 후에는 **아무것도 하지 않아도 된다.** 회의가 시작되면 Fathom 이 자동으로 참석해 녹화한다.
참석자에게는 "이 회의는 녹화되고 있습니다" 안내가 뜬다. 숨기는 것이 아니다.

### A-2. 전사 가져오기

MCP 가 연결돼 있으면 대화로 가져온다. 사용자가 회의를 특정하면 그것으로 찾는다.

- 최근 회의 목록을 보려면 회의 목록 도구를 쓴다
- 사용자가 URL 이나 통화 ID 를 주면 그것으로 바로 찾는다. **목록을 뒤지지 않는다**
- 전사 내용을 물으면 **반드시 도구를 호출해서 확인한다.** 기억으로 답하지 않는다

Zoom 세션이 끊기면 같은 회의가 여러 건으로 나뉜다. **전부 한 회의로 본다.**

전사를 확보했으면 **아래 「공통. 교정과 확정」 으로 간다.** B 경로는 건너뛴다.

### A-3. Fathom 봇이 회의에 못 들어왔을 때

**남이 호스트인 회의에서 자주 막힌다.** 봇이 대기실에 갇히고, 호스트가
「참가자」 패널을 열어 승인해야 들어온다. 호스트가 모르면 승인이 안 된다.

이때는 전사가 아예 없다. **`OBS_회의녹화.md` 를 따라 녹화한 파일로 B 경로를 쓴다.**
맥 화면 기록은 쓰지 않는다. 마이크만 잡혀 상대 발언이 사라진다.

## B 경로. 녹음 파일 전사

### B-1. 파일 위치를 받는다

사용자에게 **음성 또는 영상 파일의 전체 경로**를 묻는다. 드래그해서 놓으면 경로가 들어온다.
지원 형식: `m4a` `mp3` `wav` `mp4` `mov` `webm` 등 ffmpeg 가 읽는 것 전부.
영상이어도 된다. 음성만 알아서 뽑는다.

### B-2. 전사 실행 (이 명령 하나만 쓴다)

```bash
python3 <스킬폴더>/scripts/transcribe.py "<파일>" --out "<작업폴더>"
```

맥과 윈도우에서 같은 명령이다. 윈도우는 `python3` 대신 `py` 를 쓸 수 있다.

**`prepare_audio.py` 나 `groq_stt.py` 를 직접 부르지 않는다.**
진입점이 환경 점검, 녹음 상태 확인, 외부 전송 고지, 전처리, 전사, 사후 검증을 순서대로 한다.

| 옵션 | 언제 |
|---|---|
| (없음) | **기본. Groq 로 전사한다.** 1시간 회의가 약 1분 |
| `--offline` | 인터넷이 없거나 **외부로 내보내면 안 되는 회의**. 로컬 whisper. 녹음 길이의 약 2배 |
| `--astream 1` | OBS 녹화에서 상대방 목소리만 (0=혼합 1=시스템 2=마이크) |
| `--yes-external` | 외부 전송 확인을 건너뛴다. **사용자 승인을 받은 뒤에만 쓴다** |
| `--doctor` | 전사하지 않고 환경만 점검한다 |

### B-3. 외부 전송은 사용자에게 확인받는다

기본 경로는 **녹음을 Groq(미국) 서버로 보낸다.** 진입점이 이것을 화면에 알리고 승인을 묻는다.
에이전트가 `--yes-external` 로 그 확인을 대신 넘기지 않는다.
**외부 인사 발언, 환자 정보, 미공개 과제 내용이 있으면 `--offline` 을 쓴다.**

### B-4. 종료 코드를 확인한다

| 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 정상 | 교정 단계로 간다 |
| **2** | **전사 품질 경고** | 빈 조각·낮은 커버리지가 있다. **회의록을 확정하지 말고 사용자에게 알린다** |
| 3 | 녹음이 너무 조용함 | 원인을 확인한다. 화면 기록이면 OBS 로 다시 녹화해야 한다 |
| 1 | 준비 부족 또는 사용자 거절 | 화면의 안내를 따른다 |

결과는 `<작업폴더>/raw/` 에 있다.
`_전사메타.json` 에 커버리지와 경고가, `_실행기록.json` 에 어느 경로로 갔는지가 남는다.

## 공통. 교정과 확정 (두 경로가 여기서 만난다)

### 1. 원문을 그대로 보존한다

전사 원문을 `회의록/<날짜>_<주제>_원본사본.md` 에 verbatim 저장한다.
**원문은 고치지 않는다.** front matter에 `status: 원본사본` 을 넣는다.

### 2. 용어를 대조한다

표기 우선순위는 정해져 있다.

```
① 주간보고서  >>  ② 온톨로지·정의문서  >>  ③ 메일·원장  >>  ④ 전사
```

**전사가 가장 낮다.** 대조할 대상은 인물, 기관, 제품, 과제명, 금액, 기간이다.

| 어디를 보나 | 무엇을 확인 |
|---|---|
| SSOT `00_공통/50_온톨로지/사람/` | 이름과 직함. 전사는 이름을 자주 틀린다 |
| SSOT `00_공통/50_온톨로지/조직/` | 기관명 정식 표기 |
| SSOT `{{DEPT_ROOT}}/10_과제/` | 과제 정식 명칭. 줄여 부른 말을 정식명으로 |
| 태스크 원장 `rpbd-infra/data/tasks/ledger.jsonl` | 숫자와 기한. **숫자는 문서 값을 쓴다** |
| 그 과제 폴더의 `_README.md` · `CLAUDE.md` | 과제 맥락. 무엇을 하는 일인지 |

실제로 걸렸던 것들: 「고양이 AI」는 고영향 AI, 「뉴드라이브」는 U드라이브,
「SST」는 SSOT, 「7곡」은 칠곡, 사람 이름이 통째로 다른 사람으로 바뀐 경우도 있었다.

**확정할 수 없는 것은 고치지 않는다.** 미확정으로 표시해 사람에게 올린다.

### 3. 교정기록을 남긴다

`workspace/교정기록_<회의ID>.md` 에 무엇을 무엇으로 고쳤는지와 근거를 적는다.
이것은 작업 기록이다. **확정본에 싣지 않는다.** 회의록은 회의의 기록이지 작성자의 감사로그가 아니다.

### 4. 본문에 반영한다

교정한 내용을 확정본 본문까지 고친다.
교정표만 만들고 본문을 그대로 두면 서로 모순된다.

### 5. 1차 브리핑과 오답노트

**확정하기 전에 사람에게 보여준다.** 다음을 한 번에 전한다.

| 무엇 | 어떻게 |
|---|---|
| 회의록 초안 | 절 구성대로 작성한 것 |
| 고친 것 | 전사 >> 확정 표기 목록 |
| **미확정 항목** | 문맥과 함께. **사람이 채우도록 빈칸을 둔다** |
| 화자 식별 여부 | 전사에 화자 구분이 없으면 발언 귀속을 명시적으로 밝힌다 |

사용자가 수정하면 그것을 반영한다. **사람이 고친 것이 정본이다.**
같은 실수가 반복되면 규칙 한 줄로 만들어 오답노트에 추가한다.

### 6. SSOT로 (확정본과 교정기록을 함께)

교정을 마친 것(`status: final`)을 SSOT 회의록 폴더로 올린다.
**교정기록(오답노트)도 함께 올린다.** 왜 그렇게 고쳤는지 남아야 다음 사람이 이어받는다. (규약 변경 2026-09-21 Roy: 에이전트 산출물이 로컬에만 남으면 팀원이 이어받을 수 없다)

단, 전사 원문은 발언 그대로라 보안 등급(공통규약 §6)을 먼저 판정한다. S2 이상이면 경로만 남긴다.

SSOT 회의록 위치: `{{DEPT_ROOT}}/40_커뮤니케이션/회의록/`

## 회의록 절 구성

```yaml
meeting_id: PRJ-2026-09-14
type: 부서 정기회의
date: 2026-09-14
source: fathom.video/calls/... 또는 녹음파일명
sensitivity: 사내한정
status: final
```

| 절 | 내용 |
|---|---|
| 1. 개요 | 참석자, 형식, 근거. 무게중심 몇 가지 |
| 2. 핵심 논의 | 주제별 소절. 발언 취지를 재구성한다 |
| 3. 결정사항 | 표. 구분 / 내용 / 주체 |
| 4. 액션아이템 | 표. 담당 / 내용 / 기한 |
| 5. 특이사항 | 전사 품질, 미확정 항목, 화자 식별 실패 등 |

## 지키는 것

- **원문은 교정하지 않는다.** 사본에만 손댄다
- **숫자는 문서 값을 쓴다.** 전사에서 들린 숫자를 믿지 않는다
- **확정할 수 없으면 미확정으로 올린다.** 그럴듯하게 채우지 않는다
- **교정기록은 확정본 본문에 싣지 않는다.** 별도 파일로 SSOT 에 함께 올린다 (규약 2026-09-21)
- 개인 실명과 금액을 한 줄에 함께 쓰지 않는다
- em dash를 쓰지 않는다
