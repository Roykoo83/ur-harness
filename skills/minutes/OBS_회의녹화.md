# Fathom 이 못 들어올 때는 OBS 로 녹화한다

## 왜 필요한가

**Fathom 은 내가 호스트일 때만 안정적이다.** 남이 연 방에서는 봇이 대기실에 갇히고,
외부 호스트가 「Fathom Notetaker」라는 낯선 참가자를 승인해줘야 들어온다.
비밀번호 없이 링크만으로 입장 가능한 방이어도 **대기실이 켜져 있으면 승인은 별개다.**

2026-09-22 플랫폼 이관 회의에서 실제로 이것이 막혔고,
대신 맥 화면 기록을 썼다가 **상대 발언이 전부 유실**됐다.

## 화면 기록을 쓰지 않는 이유

macOS 화면 기록(`screencapture -g`)은 **기본 입력장치, 즉 마이크만** 잡는다.
Zoom 소리는 스피커로 나가므로 녹화에 담기지 않는다.

| | 2026-09-22 화면 기록 | 2026-09-23 OBS |
|---|---|---|
| 전체 음량 | -38.4 dB | **-13.3 dB** |
| 45분 중 정상 음량 | 약 10.5분 | 전 구간 |
| 상대 발언 | **없음** | 담긴다 |

25dB 차이다. 화면 기록은 회의 녹화에 쓸 수 없다.

## 쓰는 법

1. **OBS 를 연다.** 프로파일과 씬이 `회의녹화` 로 맞춰져 있는지 확인한다
   (좌하단 프로파일, 우하단 장면 모음)
2. **녹화 시작**을 누른다
3. 회의가 끝나면 **녹화 중지**
4. 파일은 `~/Movies/회의녹화/회의_날짜_시각.mp4` 에 생긴다
5. Claude Code 창에 그 파일을 끌어다 놓고 "회의록 만들어줘"

## 무엇이 녹음되나

오디오가 **트랙 3개로 분리**되어 저장된다.

| 트랙 | 내용 | 쓰임 |
|---|---|---|
| 1 | 혼합 (시스템 + 마이크) | 기본. 회의록 전사는 이것을 쓴다 |
| 2 | **시스템 오디오** | 상대방 목소리만. 내 목소리를 빼고 싶을 때 |
| 3 | **내 마이크** | 내 목소리만 |

트랙이 나뉘어 있으면 나중에 화자를 가를 여지가 생긴다.
한 트랙으로 뭉쳐 놓으면 그 여지가 사라진다.

특정 트랙만 뽑으려면:

```bash
ffmpeg -i "회의_2026-09-23_1400.mp4" -map 0:a:1 -vn 상대방만.m4a
```

`0:a:0` 이 트랙1, `0:a:1` 이 트랙2, `0:a:2` 가 트랙3 이다.

## 설정값 (이미 적용돼 있다)

| 항목 | 값 | 왜 |
|---|---|---|
| 해상도 | 1600x900 | 화면 공유 글자를 읽을 수 있는 최소선 |
| 프레임 | 15fps | 회의는 움직임이 적다. 용량을 줄인다 |
| 파일 분할 | 2GB 마다 | 긴 회의에서 파일 하나가 깨지는 것을 막는다 |
| 저장 경로 | `~/Movies/회의녹화/` | 개인 구글드라이브로 새지 않게 |
| 오디오 | 48kHz 스테레오 · 트랙당 160kbps | |

45분 회의가 대략 700MB 안팎이다.

## 처음 한 번만 필요한 권한

OBS 가 **화면 기록**과 **마이크** 권한을 요청한다. 시스템 설정에서 허용한다.
시스템 오디오 캡처는 별도 드라이버(BlackHole 등)가 **필요 없다.**
macOS 13 부터 제공되는 기능을 OBS 가 그대로 쓴다.
