# 회의록 전사 구조

갈림길은 **하나**다. 온라인 회의인가, 대면 회의인가.

```
온라인 회의 ──> Fathom ─────────────────┐
     │        (내가 호스트일 때)         │
     └──────> OBS 녹화 ──> 전처리 ─┐     │
              (봇 입장 실패 시)     │     │
                                    ├─────┼──> 정본 대조 ──> 확정본(SSOT)
대면 회의 ─────────> 전처리 ──> Groq┘     │        ▲
                        │                 │        │
                        └─> 로컬 ─────────┘   사람이 확인
                         (인터넷 없을 때만)
```

## 온라인 회의에서 Fathom 이 막히면

**Fathom 은 내가 호스트일 때만 안정적이다.** 남이 연 방에서는 봇이 대기실에 갇히고,
외부 호스트가 낯선 참가자를 승인해줘야 들어온다.
막히면 **OBS 로 녹화한다.** 맥 화면 기록은 쓰지 않는다. 마이크만 잡혀 상대 발언이 사라진다.
자세한 것은 `OBS_회의녹화.md`.

## 경로

| | 온라인 | 대면 |
|---|---|---|
| 전사 | Fathom (자동) | Groq |
| 화자 구분 | 된다 | 안 된다 |
| 1시간 처리 | 자동 | 약 1분 |
| 설치 | 없음 | ffmpeg + 본인 Groq 키 |

**대면은 무조건 Groq 다.** 로컬 Whisper 는 인터넷이 없을 때 수동으로 돌리는 예외 경로이고,
평소에 쓰는 경로가 아니다. 로컬은 1시간 녹음에 1시간 40분이 걸린다.

## 실행은 명령 하나다

```bash
python3 ~/.claude/skills/minutes/scripts/transcribe.py "<파일>" --out "<작업폴더>"
```

맥·윈도우 공통이다. 이 진입점이 환경 점검 >> 녹음 상태 확인 >> 외부 전송 고지 >>
전처리 >> 전사 >> 사후 검증을 순서대로 한다.
`prepare_audio.py` 나 `groq_stt.py` 를 직접 부르지 않는다.

| 종료 코드 | 뜻 |
|---|---|
| 0 | 정상 |
| 2 | 전사 품질 경고. **확정하지 마라** |
| 3 | 녹음이 너무 조용함 |
| 1 | 준비 부족 또는 사용자가 전송을 거절 |

환경 점검만 하려면 `--doctor`, 고치고 나서 회귀 시험은 `selftest.py` 다.

## 전처리는 자동이다

대면 녹음을 Groq 로 보내기 전에 진입점이 알아서 한다.

1. 영상이면 음성만 추출한다
2. 16kHz 모노 Opus 로 변환한다 (Groq 가 어차피 16kHz 모노로 내린다)
3. 25MB 를 넘으면 **무음 지점에서** 쪼갠다. 단어 중간을 자르지 않는다
4. 조각별 시작 시각을 기록해 두었다가, 전사 후 원본 시간축으로 되돌린다

기본은 Opus 32kbps 다. **25MB 에 116분**이 들어가서 2시간 회의는 한 번에 나간다.

압축이 전사 결과를 얼마나 바꾸는지는 아직 확정하지 못했다. 같은 파일을 원본과
Opus 24kbps 로 각각 돌렸을 때 87% 만 일치했는데, 방향이 일정하지 않았다
(복지부는 줄고 IRB 는 오히려 살아났다). 검증에 쓴 turbo 모델 자체가 불안정해서
코덱 탓인지 모델 탓인지 가르지 못했다. 그래서 24 가 아니라 32 로 둔다.
실제로 쓰면서 맞춘다.

## Groq 무료 한도는 계정당이다

| 항목 | 한도 |
|---|---|
| 요청당 파일 | 25MB |
| 시간당 오디오 | 2시간 |
| 하루 오디오 | 8시간 |
| 분당 요청 | 20회 |

**키는 각자 본인 계정으로 발급한다.** 한 키를 나눠 쓰면 한도를 나눠 쓰게 되고,
그 키가 막히면 전원이 멈춘다. 무료라 각자 받는 데 비용이 들지 않는다.

## 전사가 끝난 뒤는 경로와 무관하게 같다

1. 전사 원문을 **고치지 않고** 보존한다
2. SSOT 온톨로지로 이름·과제명·약어를 대조한다. 전사보다 정본을 믿는다
3. 확정 못 한 것은 빈칸으로 남기고 문맥만 보여준다
4. 사람이 채운 것이 정본이 된다
5. 확정본과 **교정기록을 함께** SSOT 에 올린다. 왜 그렇게 고쳤는지가 남아야
   다음 사람이 이어받는다 (규약 2026-09-21). 전사 원문은 보안 등급을 판정한 뒤
   S2 이상이면 경로만 남긴다
