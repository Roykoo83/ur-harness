# 00 · 이관 체크리스트

담당자가 바뀌거나 서버를 옮길 때 이 순서로 한다. **빠뜨리면 조용히 멈추는 항목에 ⚠ 를 붙였다.**

## 한눈에

```
구 담당자가 하는 일          신 담당자가 하는 일
─────────────────────      ─────────────────────
1 인계 목록 확정            4 서버 준비 · 설치
2 조직 자산 소유 이전  ───▶  5 설정 채우기 (operator 블록)
3 서비스 중지               6 재인증 2건
                           7 서비스 기동 · 검증
```

**조직 자산(공유 드라이브 · 봇 · 서비스계정)은 그대로 쓴다.** 조직 소유지 개인 것이 아니다.
실제로 다시 해야 하는 것은 **개인 계정으로 묶인 인증 2건**뿐이다.

## 구 담당자

- [ ] **인계 목록 확정** — 아래 「무엇이 바뀌고 무엇이 그대로인가」를 함께 읽는다
- [ ] ⚠ **서비스계정 키 위치 확인** — `~/.nworks/private_*.key`. 조직 자산이므로 **새 담당자에게 안전한 경로로 전달**한다 (메신저·메일 금지. 암호화 저장소 또는 직접 전달)
- [ ] 봇 ID·시크릿, 클라이언트 ID·시크릿 전달 (같은 방식)
- [ ] 채널 ID 목록 전달 (부서방·아카이빙 대상)
- [ ] ⚠ **서비스 중지** — 두 사람이 동시에 돌리면 정본에 중복이 쌓인다
      `systemctl --user disable --now 'ur-*.timer'`
      (macOS `launchctl bootout` · Windows `Get-ScheduledTask -TaskPath "\UR Harness\" | Disable-ScheduledTask`)
- [ ] 마지막 상태 기록 — `python3 core/gate_check.py --json > handover-state.json`

## ⚠ 이식할 때 유념할 것 (원 운영 환경은 개발자 개인 맥이었다)

이 하네스는 **원 운영자의 맥 한 대에서 만들고 검증했다.** 새 담당자가 자기 시스템으로 옮길 때
아래는 「돌기는 도는데 결과가 0건」인 상태로 조용히 깨질 수 있다. 2026-10 맥 안에서 스케줄러만
옮겼을 때도 실제로 이렇게 깨졌다(아래 「고장 9」).

- [ ] ⚠ **쓰는 쪽과 읽는 쪽의 경로가 같은지 확인한다.** 수집기(`nwctl mail-pull`)가 저장하는
      `output/raw_mail/` 과 파서·브리핑이 읽는 `output/raw_mail/` 은 **같은 프로젝트 루트 아래**여야 한다.
      설치 후 `find . -path "*raw_mail*" -name "*.json" | head` 로 한 곳에만 쌓이는지 본다
- [ ] ⚠ **검증은 종료코드가 아니라 건수로 한다.** 첫 수집 후 `workspace/mail_cycle.log` 에서
      `parse[…]: {"parsed": N}` 의 N 이 0이 아니어야 한다. 아침 브리핑 하단
      `📮 메일 수집 정상(…) · 수집 N건 · 정리 N건` 줄로도 확인된다
- [ ] ⚠ **터널은 서비스 이름이 환경마다 다르다.** 감시기(`tunnel_guard`)는 떠 있는 터널 작업과
      그 로그를 스스로 찾는다. 이식 후 `workspace/tunnel_guard.log` 에 「URL 미확인」이 반복되면
      터널 로그 위치를 맞춘다. 터널 주소가 바뀌면 봇 콜백이 재등록되는지(로그 「콘솔 콜백 재등록 완료」) 확인한다
- [ ] ⚠ **첫 U 동기화는 오래 걸린다.** 기존 원본 수천 건을 대조하므로 30분 제한을 넘길 수 있다.
      이식 직후 한 번은 손으로 `rclone copy` 를 시간 제한 없이 돌려 두면 이후 회차가 짧아진다
- [ ] ⚠ **과거 원본을 함께 옮긴다.** `output/raw_mail/`·`output/raw_messenger/` 를 옮기지 않으면
      메신저 대화록 정리본이 0건이 되고, 미러 동기화가 클라우드 쪽 정리본을 지울 수 있다
- [ ] ⚠ **서비스마다 「실제 산출물」을 본다.** 서비스가 정상 종료해도 엉뚱한 프로그램에 연결돼 있으면
      아무것도 만들지 않는다. 특히 정본 색인은 `_시스템/색인/manifest.json` 의 `generated` 가
      3시간 안쪽인지, `files.tsv` 행 수가 드라이브 파일 수와 비슷한지 본다 (`python3 core/ssot_index.py --dry`)
- [ ] **메일 API 토큰 만료**: Access Token 1시간 · Refresh Token 90일 · Rotation On(콘솔에서 확인).
      수집이 돌 때마다 90일이 연장되므로 **90일 연속으로 수집이 멈추지만 않으면** 만료되지 않는다.
      만료일은 브리핑 하단 `🔑 … 토큰 만료 D-n` 으로 매일 보인다. 계정을 바꾸면 재동의(`nwctl ua-auth`)
- [ ] **기계 상태에 기대는 부분**: 맥 잠자기 직후 회차는 DNS 오류로 실패할 수 있다(다음 회차에 자동 회복).
      상시 켜진 서버로 옮기면 사라지는 문제다

## 신 담당자

- [ ] **서버 준비** — Ubuntu 22.04+ 권장. 상시 켜져 있어야 한다
- [ ] `git clone` → 설치 점검
      · Linux·macOS: `bash install/bootstrap.sh`
      · Windows: `powershell -ExecutionPolicy Bypass -File install\bootstrap.ps1`
- [ ] `cp config/harness.example.yaml config/harness.yaml` → 값 입력
- [ ] ⚠ **`operator:` 블록을 자기 것으로** — account · name · workspace
- [ ] ⚠ **재인증 ①: 드라이브** — `rclone config reconnect SSOT_rw:` (새 Google 계정 동의)
- [ ] ⚠ **재인증 ②: 그룹웨어 메일** — `python3 agents/nworks/nwctl ua-auth <봇계정>`
      메일은 **사용자 계정 전용 API** 라 계정이 바뀌면 동의를 다시 받아야 한다
- [ ] `python3 install/configure.py --all`
- [ ] 서비스 등록 (configure 가 출력한 명령)
      · Linux: systemd 유닛 · macOS: launchd · **Windows: 작업 스케줄러** (`09_윈도우_설치.md`)
- [ ] `loginctl enable-linger $USER` — 로그아웃해도 돌게
- [ ] **검증** — 아래 「인수 검증」

## 무엇이 바뀌고 무엇이 그대로인가

| | 바뀌나 | 왜 |
|---|---|---|
| 공유 드라이브 (정본·원천) | **그대로** | 조직 소유. 폴더도 ID도 같다 |
| 봇 계정 · 봇 ID | **그대로** | 조직 소유 |
| 서비스계정 (조직도·캘린더) | **그대로** | 조직 소유. 키 파일만 옮긴다 |
| 채널 ID | **그대로** | |
| 사내 위키 토큰 | 조직 발급이면 그대로 | 개인 토큰이면 재발급 |
| **개인 Google 계정** | **바뀐다** | 드라이브 OAuth 주체 |
| **그룹웨어 메일 동의** | **바뀐다** | 사용자 계정 전용 API |
| **작업 디렉토리 경로** | **바뀐다** | 서버가 다르다 |
| 작업로그 폴더 이름 | 바뀐다 | 담당자 이름 |

## 인수 검증

이 넷이 통과하면 이관이 끝난 것이다.

```bash
python3 install/configure.py --check     # 1. 설정이 다 찼는가
python3 core/gate_check.py               # 2. 정합성 게이트
systemctl --user list-timers 'ur-*'      # 3. 타이머가 예약됐는가
                                        #    (Windows: schtasks /Query /TN "UR Harness\UR-watchdog")
```

4. **90분 기다린 뒤** 정본에 새 자료가 올라왔는지 본다 — 수집 60분 + 승격 30분.
   안 올라오면 `journalctl --user -u ur-nworks-cycle -n 50` 을 본다.

## 자주 막히는 곳

| 증상 | 원인 | 조치 |
|---|---|---|
| 수집이 0건 | 메일 재인증 안 함 | `nwctl ua-auth` |
| 승격이 `blocked` | 판정 대장이 없음 | `nworks-cycle` 을 한 번 수동 실행 |
| 색인이 멈춤 | 신선도 가드 작동 (정상) | `_시스템/상태/색인_보류.json` 의 사유를 본다 |
| 타이머가 안 돎 | linger 미설정 | `loginctl enable-linger $USER` |
| 쓰기 거부 | 쓰기 구역표 위반 (정상) | 사람 구역은 사람이 쓴다 |
