# 01 · 관리자 온보딩

하네스를 **설치하고 유지하는 사람**을 위한 문서. 쓰기만 하는 사람은 `02_사용자_온보딩.md`.

## 1. 하네스가 무엇을 하는가

```
그룹웨어 · 클라우드 드라이브 · 사내 위키 · 회의 전사
        │ 공식 API (읽기)
        ▼
  자동 서비스 17개 ──┬─▶ 원천 보관 (전량 · 읽지 않는다)
                     └─▶ 정본(SSOT) ──▶ 구성원의 AI
                           계약 · 스킬 · 관측
```

관리자가 지키는 것은 **셋**이다.

1. **정본이 신선한가** — 수집·승격이 돌고 있는가
2. **관측이 살아 있는가** — 이상을 15분 안에 알려주는가
3. **계약이 지켜지는가** — 게이트가 통과하는가

## 2. 설치

```bash
git clone https://github.com/<owner>/ur-harness.git && cd ur-harness
bash install/bootstrap.sh                       # 점검 + 의존성
# Windows: powershell -ExecutionPolicy Bypass -File install\bootstrap.ps1
#          이후 절차는 09_윈도우_설치.md 를 따른다
cp config/harness.example.yaml config/harness.yaml
$EDITOR config/harness.yaml                     # 값 입력
python3 install/configure.py --all              # 치환 + 유닛 생성
```

`configure` 가 출력한 명령을 그대로 실행한다.
`--all` 은 돌고 있는 OS 를 보고 고른다 — Linux `--units` · macOS `--launchd` · Windows `--tasks`.
**어느 쪽이든 경로는 설정에서 온다.** 스케줄러 파일을 손으로 쓰지 않는다 —
손으로 쓰면 만든 사람의 홈·파이썬 경로가 박히고, 담당자가 바뀔 때 전부 깨진다.
Linux 는 `loginctl enable-linger $USER` 를 함께 넣어야 로그아웃 후에도 돈다.
Windows 는 각 작업의 **'로그온 여부에 관계없이 실행'** 이 같은 역할을 한다 (`09_윈도우_설치.md` §4).

### 드라이브 원격 만들기

정본 읽기·쓰기는 **Drive API** 로 한다. 마운트는 쓰지 않는다 — 조용히 뒤처지기 때문이다.

```bash
rclone config
#  n) 새 원격  →  이름: SSOT_ro   →  종류: drive
#  scope: drive.readonly          →  team drive: 정본 드라이브 선택
#  같은 방식으로 SSOT_rw (scope: drive)  ·  gdrive (원천 드라이브)
rclone lsf SSOT_ro: --max-depth 1     # 확인
```

읽기와 쓰기를 **따로 만드는 이유**는 사고를 줄이기 위해서다. 읽기만 하는 작업이
실수로 쓰는 일을 구조적으로 막는다.

## 3. 매일·매주 보는 것

| 주기 | 무엇 | 명령 |
|---|---|---|
| 수시 | 서비스가 도는가 | `systemctl --user list-timers 'ur-*'` |
| 매일 | 실패한 서비스 | `systemctl --user list-units 'ur-*' --failed` |
| 매일 | 관측 지표 | 정본 `_시스템/상태/` 의 신선도 파일 |
| 주 1회 | 정합성 게이트 | `python3 core/gate_check.py` |
| 주 1회 | 익명화 (저장소를 고쳤다면) | `python3 scan.py .` |

### 게이트가 보는 것

`gate_check` 는 **계약과 현실이 맞는지**를 본다. 통과 못 하면 숫자로 알려준다.

- 정본에 업무 무관 자료가 섞였는가 (누출)
- 판정 대장에 없는 파일이 정본에 있는가 (고아)
- 계열 경계가 깨졌는가
- 폐지된 경로가 코드에 되살아났는가

## 4. 고장났을 때

**원칙: 「확인 못 했다」와 「통과」를 구별한다.** 확인이 안 되면 통과시키지 않는다.

| 증상 | 먼저 볼 것 | 흔한 원인 |
|---|---|---|
| 수집 0건 | `journalctl --user -u ur-nworks-cycle -n 50` | 메일 동의 만료 → `nwctl ua-auth` |
| 승격 `blocked` | 판정 대장 존재 여부 | 수집이 먼저 돌아야 한다 |
| 색인 `보류` | `_시스템/상태/색인_보류.json` | **정상 동작** — 원본과 어긋나서 멈춘 것 |
| 봇 발신 실패 | 봇 시크릿 · 채널 ID | `03_봇_게이트웨이_연동.md` |
| 전사 실패 (코드 2) | 녹음 품질 | **회의록을 확정하지 말 것** |

### 되돌리기

- 정본 삭제는 **전부 휴지통을 거친다.** 드라이브 휴지통에서 복원한다
- 자동화는 **자기가 만든 파일만** 덮어쓴다. 사람 파일은 건드리지 않는다
- 서비스를 멈추려면 `systemctl --user disable --now ur-<이름>.timer`

## 5. 설정을 바꿀 때

```bash
$EDITOR config/harness.yaml
python3 install/configure.py --all     # build/ 재생성 + 유닛 갱신
systemctl --user restart 'ur-*.timer'
```

저장소 원본은 자리표시자를 유지한다. 실제 값은 `config/harness.yaml` 과 `build/` 에만 있고
둘 다 커밋되지 않는다.

## 6. 하지 말 것

| | 왜 |
|---|---|
| 정본을 마운트(탐색기)로 자동 수정 | 캐시가 조용히 분기한다. 쓰기는 API 하나로 |
| 한 경로에 두 주체가 쓰기 | 동기화 충돌. 경로마다 쓰는 주체는 하나 |
| 자동화에 삭제 권한 주기 | 남의 파일을 지운 사고가 실제로 있었다 |
| 가드 실패를 "통과"로 처리 | 자동 실행에서 가드가 꺼진 사고가 있었다 |
| 비밀값을 저장소에 넣기 | `scan.py` 가 막지만, 넣지 않는 것이 먼저다 |
