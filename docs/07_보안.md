# 07 · 보안

## 1. 비밀값은 저장소에 없다

| 무엇 | 어디에 | 권한 |
|---|---|---|
| 그룹웨어 클라이언트 ID·시크릿 | `~/.nworks/config.json` | 600 |
| 서비스 계정 개인키 | `~/.nworks/*.key` | 600 |
| 사용자 토큰 캐시 | `~/.nworks/ua_token_*.json` | 600 |
| 드라이브 OAuth | `~/.config/rclone/rclone.conf` | 600 |
| 조직 고유 설정 | `config/harness.yaml` | **커밋 금지** |

```bash
chmod 700 ~/.nworks && chmod 600 ~/.nworks/*
```

저장소에는 `.example` 파일만 있다. 실제 값은 `.gitignore` 로 막혀 있고,
`scan.py` 가 커밋 대상에서 비밀값 패턴을 한 번 더 찾는다.

## 2. 공개 저장소에 올리기 전

```bash
python3 scan.py .
```

**0건이어야 올린다.** 무엇을 잡는지는 아래와 같다.

| | |
|---|---|
| 개인 식별자 | 사람 이름 · 개인 계정 · 조직 고유명 (목록은 `scan.local.json` — 커밋하지 않는다) |
| 환경 고유값 | 개인 홈 경로 · 드라이브 ID |
| 비밀값 | API 키 접두 · PEM 블록 · 토큰 리터럴 |
| 연락처 | 이메일 · 전화번호 |

`# scan:allow` 주석이 붙은 줄과 `example.org` · `<자리표시자>` 는 통과한다.

> **한 번 공개된 것은 지워도 캐시와 포크에 남는다.** 커밋 전에 거르는 것이 유일한 방법이다.

## 3. 유출이 의심되면

1. **즉시 폐기하고 재발급** — 지우는 것보다 무효화가 먼저다
2. 커밋했다면 히스토리까지 지워야 한다 (`git filter-repo`). 공개됐다면 재발급이 유일한 해법
3. 무엇이 언제부터 노출됐는지 기록한다

## 4. 데이터 취급

| | 원칙 |
|---|---|
| 개인 식별 + 금전 결합 문서 | **정본에 올리지 않는다.** 원천에 두고 경로만 참조 |
| 회의 녹음 | 외부 전사로 보낼 때 **화면에 알리고 승인을 받는다** |
| 민감 회의 | 로컬 전사 경로 (`--offline`) |
| 메일 원문·첨부 | 원천에만. 정본에는 정제된 것만 |
| 전화번호·생년월일·개인 메일 | 온톨로지에 넣지 않는다 |

## 5. 권한 설계

| | |
|---|---|
| 읽기와 쓰기 원격을 분리 | 읽기 작업이 실수로 쓰는 것을 구조적으로 막는다 |
| 자동화에 삭제 권한을 주지 않는다 | 남의 파일을 지운 사고가 실제로 있었다 |
| 삭제는 휴지통 경유 | 되돌릴 수 있게 |
| 경로마다 쓰는 주체 하나 | 두 주체가 쓰면 충돌하고 사본이 생긴다 |
| 보안 등급은 라벨이지 권한이 아니다 | 접근 통제는 드라이브 권한이 한다 |

## 6. 접근 범위

| 대상 | 범위 |
|---|---|
| 서비스 계정 | 조직도 · 캘린더 읽기. **메일은 불가** |
| 사용자 토큰 | 그 계정의 메일. 계정이 바뀌면 재동의 |
| 봇 | 초대된 방에만 |
| 드라이브 | 공유 드라이브 멤버십 범위 |

**필요한 스코프만 켠다.** 쓰지 않는 권한은 사고 면적이다.

## 7. 점검 주기

| 주기 | 무엇 |
|---|---|
| 저장소 수정 시 | `scan.py .` |
| 월 1회 | `~/.nworks` 권한 · 저장소에 들어간 파일 목록 |
| 분기 1회 | 토큰·키 만료. 쓰지 않는 스코프 회수 |
| 담당자 변경 시 | 구 담당자 토큰 폐기 · 접근 권한 회수 |
