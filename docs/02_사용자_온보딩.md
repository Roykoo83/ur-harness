# 02 · 사용자 온보딩

**설치할 것이 없습니다.** 세 단계면 시작합니다.

## 1. 시작하기 — 세 단계

```
1. 공유 드라이브에 접근한다            5분   (관리자에게 권한 요청)
2. 그 폴더에서 AI 클라이언트를 연다     1분
3. 온보딩이 스스로 돕니다              10분
```

**2단계**는 이렇게 합니다.

- 데스크톱 앱: Code 탭 → 그 폴더 열기
- 터미널(CLI): 그 폴더로 이동한 뒤 실행

폴더를 열면 진입점 파일이 자동으로 읽히고, 나머지는 AI가 가져옵니다.

**3단계**에서 AI가 다섯 가지를 묻습니다 — 누구인지, 직책과 주 업무, 담당 과제,
쓰는 도구, 답변 형식. OS·경로·설치된 프로그램은 **묻지 않고 직접 확인**합니다.

## 2. 내 설정은 세 블록

```
[조직 공통]  정본 경로 · 규약 포인터       ← 온보딩이 만들고 갱신한다
[내 환경]    OS · 클라이언트 · 런타임 유무   ← 컴퓨터를 바꾸면 버리고 다시
[나의 방식]  답변 형식 · 되돌리기 전 묻기    ← 내 것. 컴퓨터를 바꿔도 따라옵니다
```

섞어 두지 마십시오. 섞으면 컴퓨터를 바꿀 때 「나의 방식」까지 날아갑니다.

## 3. 할 수 있게 되는 것

| | 어떻게 |
|---|---|
| **찾으면 나온다** | 메일·문서·회의록·일정이 과제별로 한 곳에. 업무 무관 자료는 애초에 안 들어옵니다 |
| **전원이 같은 걸 본다** | 새 자료는 최대 90분 안에 모두에게 보입니다 |
| **회의가 저절로 남는다** | 녹음 파일 하나로 회의록 초안까지 |
| **모르면 모른다고 한다** | AI가 추측으로 답하지 않고 근거와 「미발견」을 함께 보고합니다 |
| **반복이 도구가 된다** | 자주 하는 일은 스킬로 |

## 4. 스킬 다섯 — 전원 사용

역할이나 OS로 막지 않습니다.

| 스킬 | 언제 부르나 |
|---|---|
| **과제 작업 시작** | "과제 시작" · 어디까지 했는지 브리핑받고 일을 시작할 때 |
| **회의록** | "회의록 만들어줘" · 녹음 파일이나 온라인 회의 전사가 있을 때 |
| **구성도** | "구성도 그려줘" · 흐름도·구조도가 필요할 때 |
| **대시보드** | "대시보드 고치기" · 부서 현황판을 바꿀 때 |
| **사내 수집** | "이 페이지 모아줘" · 로그인이 필요한 사내 페이지 |

프로그램이 깔려 있으면 빨라질 뿐, **없다고 못 하게 되지 않습니다.**
느린 길로 갈 때는 무엇이 빠졌는지 알려줍니다.

## 5. 지켜야 할 것 셋

1. **내 과제 폴더에 씁니다.** 남의 폴더·자동화 폴더는 읽기만
2. **「없다」고 하기 전에 탐색 보고를 받습니다** — 신선도 · 읽은 것 · 핵심 · 미발견
3. **되돌리기 어려운 일(삭제·이동) 전에는 확인을 받습니다**

## 6. 일한 뒤에는

작업로그를 남깁니다. 과제 폴더 안의 작업로그 폴더에 날짜와 주제로.
무엇을 읽고 무엇을 만들었는지, 못 찾은 것은 무엇인지 적습니다.

> 이게 쌓이면 **"전에 어떻게 했더라"가 사라집니다.** 다음 사람도 같은 것을 다시 찾지 않습니다.

## 7. 막히면

| 증상 | 할 일 |
|---|---|
| 자료가 안 보인다 | AI에게 "신선도 확인하고 다시 찾아줘" — 캐시가 뒤처졌을 수 있습니다 |
| AI가 엉뚱한 이름을 쓴다 | 회의록이면 교정 단계에서 고칩니다. 반복되면 관리자에게 |
| 스킬이 안 돈다 | 그 환경에 없는 프로그램을 쓰는 단계일 수 있습니다. 무엇이 빠졌는지 알려줍니다 |
| 쓰기가 거부됐다 | 자동화 전용 폴더입니다. 정상 동작이니 내 폴더에 씁니다 |
