# 06 · 운영과 장애 대응

이 하네스가 실제로 겪은 고장과, 각각을 다시 잡는 장치. **다른 조직에서도 같은 모양으로 난다.**

## 설계 원칙 — 왜 이렇게 만들었나

> **성숙도는 "도구를 얼마나 썼나"가 아니라 "거짓 확신이 얼마나 빨리 들키는가"로 잰다.**

| 단계 | 뜻 |
|---|---|
| D0 | 아무도 모른 채 결과가 나간다 |
| D1 | 사후에 사람이 알아챈다 |
| D2 | 기계가 로그에 남긴다 |
| **D3** | **낡은 상태로 결론 내리기 전에 멈춘다** ← 여기를 목표로 한다 |
| D4 | 자동 복구 |

## 고장 8건 → 장치 8개

| # | 고장 | 지금 막는 것 |
|---|---|---|
| 1 | 자동화가 구성원 파일 7건을 지웠다 | 동기화 명령을 `sync`→`copy` 로 · 쓰기 구역표 |
| 2 | 클라우드 자리표시자에 추기 → 원문 유실 | 한 파일에 API·마운트 혼용 금지 |
| 3 | 캐시가 8일 뒤처진 채 결론을 냈다 | 신선도 지표 + 15분 주기 감시 |
| 4 | 폐지된 폴더를 보고 "진전 없음"으로 오판 | 경로 리터럴 가드 · 최신 파일 시각 먼저 확인 |
| 5 | 삭제 후 재색인 누락 → 색인 유령 446행 | 삭제-재색인을 한 묶음으로 |
| 6 | 캐시가 465건 뒤처진 채 색인을 덮었다 | **신선도 가드** (원격↔로컬 대조 후 중단) |
| 7 | 업로드 대기분이 캐시 초기화로 사라질 뻔 | **사전 백업** (실제로 작업물 2건 구조) |
| 8 | **폴백이 가드를 조용히 껐다** | 「작동 불가」와 「통과」를 구별해 보고 |

### 8번이 가장 비쌌다

가드가 필요한 도구를 못 찾자 **"통과"로 처리**해, 자동 실행 환경에서 **항상 꺼져 있었다.**
손으로 돌리면 작동하고 자동으로 돌면 꺼지는 가드였다. 그래서 자료 475건이 색인에서 사라졌다.

> **「작동 불가」와 「통과」는 다른 보고다.** 확인을 못 했으면 통과시키지 않는다.

## 증상별 대응

### 수집이 멈췄다

```bash
systemctl --user status ur-nworks-cycle
journalctl --user -u ur-nworks-cycle -n 80 --no-pager
```

| 로그에 보이는 것 | 원인 | 조치 |
|---|---|---|
| 인증 실패 · 401 | 사용자 토큰 만료 | `nwctl ua-auth <계정>` |
| 429 | 레이트 리밋 | 주기를 늘린다. 저한도 API 는 야간으로 |
| 0건 수집인데 오류 없음 | 정상일 수 있다 | 그룹웨어에서 실제 수신 여부 확인 |

### 승격이 `blocked`

판정 대장이 없으면 **일부러 멈춘다.** 필터 없이 올리면 업무 무관 자료가 섞이기 때문이다.
수집(`nworks-cycle`)을 한 번 수동 실행해 대장을 만든 뒤 다시 돌린다.

### 색인이 `보류`

```bash
cat <정본>/_시스템/상태/색인_보류.json
```

**정상 동작이다.** 원격과 로컬이 어긋나서 멈춘 것이고, 낡은 색인을 남기는 쪽이
틀린 색인을 쓰는 것보다 낫다. 사유를 보고 원인을 고친 뒤 다시 돌린다.
의도한 변화라면 `--force` 를 쓰되, **확인한 뒤에만** 쓴다.

### 게이트가 실패

```bash
python3 core/gate_check.py
```

| 항목 | 뜻 |
|---|---|
| 누출 | 업무 무관 자료가 정본에 올라갔다 |
| 고아 | 판정 대장에 없는 파일이 정본에 있다 |
| 경계 위반 | 계열 분리가 깨졌다 |
| 폐지 경로 리터럴 | 없앤 경로가 코드에 되살아났다 |

게이트가 실패하는데 코드를 안 고쳤다면 **게이트가 구조 변경에 뒤처진 것**이다.
그때는 판정식을 현재 구조에 맞춰 갱신한다 — 실제로 이 일이 한 번 있었다.

### 전사 품질 경고 (종료 코드 2)

빈 조각이나 낮은 커버리지가 있다는 뜻이다. **회의록을 확정하지 말고 사용자에게 알린다.**
코드 3은 녹음이 너무 조용한 것이니 녹음 방법을 바꾼다.

## 주기적으로 하는 일

| 주기 | 무엇 |
|---|---|
| 매일 | 실패한 서비스 확인 |
| 주 1회 | `gate_check` · 신선도 지표 |
| 월 1회 | 디스크 · 로그 용량. API 쿼터 사용량 |
| 분기 1회 | 토큰·키 만료 확인. 재인증이 필요한 것 |
| 저장소 수정 시 | `scan.py .` — 비밀값·식별자 0건 |

## 백업과 복구

| 무엇 | 어디에 | 복구 |
|---|---|---|
| 정본 | 클라우드 드라이브 | 휴지통 → 복원 (삭제는 전부 휴지통 경유) |
| 원천 | 클라우드 드라이브 | 같음 |
| 설정·키 | `~/.nworks/` · `config/harness.yaml` | **별도 백업 필요** — 저장소에 없다 |
| 산출물·상태 | 작업공간 | 재생성 가능 (원천이 남아 있으므로) |

> **반드시 따로 백업할 것은 설정과 키 둘뿐이다.** 나머지는 원천에서 다시 만들 수 있다.

## 멈춰야 할 때

둘 이상이 같은 정본에 동시에 쓰면 중복이 쌓인다. 이관·점검 중에는 서비스를 멈춘다.

```bash
systemctl --user disable --now 'ur-*.timer'    # 전부 멈춤
systemctl --user enable --now 'ur-*.timer'     # 다시 시작
```
