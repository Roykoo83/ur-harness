# 03 · 봇 · 게이트웨이 연동

메신저로 브리핑을 보내고 질문에 답하게 하는 부분. **발신만 쓸지, 수신까지 쓸지** 먼저 정한다.

## 발신과 수신은 난이도가 다르다

| | 필요한 것 | 할 수 있는 것 |
|---|---|---|
| **발신만** | 서비스 계정 + 봇 등록 | 브리핑·알림 자동 발송. **공개 주소 불필요** |
| 수신까지 | + 공개 HTTPS 콜백 | 부서방 질문에 답하기 |

> **발신부터 시작하라.** 수신은 공개 HTTPS가 필수라 터널이나 서버가 더 필요하고,
> 자체 서명 인증서로는 안 된다. 브리핑만으로도 효과의 대부분이 나온다.

## 1. 그룹웨어 앱 등록 (발신)

관리 콘솔에서 앱을 만들고 아래를 받는다. **값은 저장소에 넣지 않는다.**

| 받는 것 | 어디에 둔다 |
|---|---|
| Client ID · Client Secret | `~/.nworks/config.json` |
| Service Account 주소 | 같음 |
| 개인키 파일 (`.key`) | `~/.nworks/` · 권한 `600` |
| Bot ID · Bot Secret | 같음 |

```bash
mkdir -p ~/.nworks && chmod 700 ~/.nworks
cp config.example.json ~/.nworks/config.json   # agents/nworks/scripts 참조
chmod 600 ~/.nworks/config.json ~/.nworks/*.key
```

필요한 권한(스코프)은 쓰려는 기능만 켠다.

| 기능 | 스코프 |
|---|---|
| 브리핑 발송 | bot · bot.message |
| 메일 수집 | mail.read **(사용자 계정 전용 — 아래 2번)** |
| 캘린더 | calendar.read |
| 조직도 | directory.read |

## 2. 메일만 다르다 — 사용자 동의가 필요하다

조직도·캘린더는 서비스 계정으로 되지만 **메일은 사용자 계정 전용 API**다.
그래서 수집 계정마다 한 번 동의를 받아야 한다.

```bash
python3 agents/nworks/nwctl ua-auth <봇계정>
# 브라우저가 열린다 → 그 계정으로 로그인 → 동의
# 토큰은 ~/.nworks/ua_token_<계정>.json 에 캐시된다
```

**담당자가 바뀌면 이것을 다시 한다.** 토큰은 개인 계정에 묶인다.

## 3. 연결 확인

```bash
python3 agents/nworks/nwctl doctor        # 인증·토큰·스코프 점검
python3 agents/nworks/nwctl users         # 조직도 읽기 (서비스 계정)
python3 agents/nworks/nwctl mail-folders  # 메일 폴더 (사용자 토큰)
python3 agents/nworks/nwctl bot-send --to <채널ID> --text "연결 확인"
```

넷이 다 되면 발신 구성이 끝난 것이다.

## 4. 채널 ID 찾기

메신저에서 봇을 대상 방에 초대한 뒤, 관리 콘솔 또는 `nwctl` 로 확인해
`config/harness.yaml` 의 `channels:` 에 넣는다.

```yaml
channels:
  dept: "<부서방 채널 ID>"      # 브리핑 발송 대상
  archive: ["<방1>", "<방2>"]   # 대화를 정본에 아카이빙할 방
```

**봇이 들어가지 않은 방은 아카이빙되지 않는다.** 기록이 필요한 방에는 봇을 초대한다.

## 5. 수신까지 쓸 때 (선택)

부서방 질문에 답하게 하려면 공개 HTTPS 콜백이 필요하다.

```bash
# 터널 (고정 도메인이 없을 때)
cloudflared tunnel --url http://localhost:8977
# 출력된 https 주소를 그룹웨어 앱의 콜백 URL 로 등록
python3 install/configure.py --with agent-bridge --with tunnel-guard --units
```

터널 주소는 재시작하면 바뀐다. `tunnel-guard` 가 감시·재등록을 맡지만,
**운영에서는 고정 도메인이나 리버스 프록시를 권한다.**

### 부서방에서 쓰는 명령

봇을 멘션하거나(`@봇이름`, 표시 이름에 "bot" 이 들어가면 인식) `봇아` 로 시작한다.

| 입력 | 동작 |
|---|---|
| `@봇이름 메일수집` | 메일 수집을 바로 한 번 돌리고 「새 메일 N건」을 답한다. AI 를 거치지 않는 고정 동작이라 모델 사용 한도와 무관하다 |
| `@봇이름 <질문>` | AI 가 답한다. 운영자 외에는 읽기 전용 |

`메일수집` 은 `access.bridge` 명단의 사람만 쓸 수 있다. 5분에 한 번으로 제한하고,
정기 수집이 돌고 있으면 겹치지 않게 거절한다. 메일 인증이 끊겼으면 운영자 확인을 안내한다.
봇 표시 이름을 바꿔도 코드 수정은 필요 없다.

## 6. 전사 서비스 연동 (선택)

회의 녹음을 글로 바꾸는 부분. 두 경로를 **둘 다** 둔다.

| 경로 | 쓸 때 | 속도 |
|---|---|---|
| 외부 전사 API | 일반 회의 | 1시간 회의가 약 1분 |
| 로컬 전사 | **외부 인사·민감 정보·미공개 과제** | 녹음 길이의 약 2배 |

```yaml
transcribe:
  provider: "groq"      # 외부 API 를 기본으로
  external_ok: false    # true 로 두지 말 것 — 외부 전송 확인을 건너뛴다
```

외부로 보낼 때는 화면에 알리고 승인을 받는다. **에이전트가 그 확인을 대신 넘기지 않는다.**

## 7. 비밀값 다루기

| | |
|---|---|
| 저장 위치 | `~/.nworks/` · 권한 700/600. **저장소에 넣지 않는다** |
| 전달 방법 | 암호화 저장소나 직접 전달. **메신저·메일 금지** |
| 유출 의심 | 즉시 폐기하고 재발급. 커밋했다면 히스토리까지 지워야 한다 |
| 점검 | `python3 scan.py .` 가 커밋 대상에서 비밀값 패턴을 찾는다 |
