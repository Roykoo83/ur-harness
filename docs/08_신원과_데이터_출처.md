# 08 · 신원과 데이터 출처 — 코드에 사람을 박지 않는다

> 이 문서는 규칙이다. 여기서 벗어난 코드는 공개 게이트(`scan.py`)가 막는다.

## 1. 왜 이 규칙이 있나

사람의 이름·사용자ID·메일을 코드에 적으면 세 가지가 **동시에** 망가진다.

| 망가지는 것 | 어떻게 |
|---|---|
| 공개 | 저장소에 개인 식별자가 남는다. 한 번 올라가면 지워도 포크·캐시에 남는다 |
| 이관 | 담당자가 바뀔 때마다 코드를 고쳐야 한다. 고칠 곳을 하나라도 놓치면 알림이 엉뚱한 사람에게 간다 |
| 정합 | 조직도와 코드가 따로 논다. 퇴사자가 코드에만 남아 있어도 아무도 모른다 |

실제로 2026-10-16 공개본에 개인 호칭 127곳 · 조직명 54곳 · 사용자ID 5곳이 남았다.
게이트는 "위반 0건"을 보고했다 — 금지어 목록에 그 단어가 없었기 때문이다.
**금지어를 늘리는 것으로는 못 막는다. 애초에 적지 않아야 막힌다.**

## 2. 정본은 이미 둘 있다

```
그룹웨어 조직도            SSOT 온톨로지
(directory API)           00_공통/50_온톨로지/
    │                         │
    │ 재직 · 부서 · 직급        │ 과제 배정 · 교신 관계 · 이력
    │ 메일 · 사용자ID          │ (조직도를 받아 적고 맥락을 더한 것)
    └──────────┬──────────────┘
               ↓
        core/lib/identity.py        ← 코드는 여기만 부른다
```

`roster_sync` 가 조직도를 온톨로지 `사람/` 으로 매일 맞춘다.
**조직도가 신원의 정본이고, 온톨로지가 맥락의 정본이다.**

## 3. 그래서 코드가 가지는 것은 "역할" 하나뿐

`config/harness.yaml`:

```yaml
operator:
  account: "<운영자 메일>"      # ← 이관 때 바꾸는 곳은 여기 하나

access:                          # 기능별 대상 — 메일 주소만 적는다
  calendar: []                   #   이름·ID 는 적지 않는다. 조직도가 안다
  bridge: []
```

코드:

```python
from lib.identity import alert_target, targets, person

tgt = alert_target()             # ("user", id) 또는 ("channel", id) 또는 None
for t in targets("calendar"):    # [{"email", "name"}, …]
    ...
p = person(email=addr)           # 온톨로지 레코드 (부서·직급·과제)
```

## 4. 반드시 지킬 네 가지

**① 사람 이름을 코드·설정에 쓰지 않는다**
역할로 쓴다 — `운영자` · `구성원 A`. 설정에는 **메일 주소만** 적는다.
이름이 필요하면 `identity.targets()` 나 `person()` 이 조직도·온톨로지에서 읽어 온다.

**② 사용자ID·채널ID를 코드에 쓰지 않는다**
메일 → ID 변환은 `identity.user_id_for()` 가 한다. 결과는 작업공간에 24시간 캐시한다.
굳이 고정해야 하면 `operator.user_id` 로 설정에 둔다 — 저장소에는 올라가지 않는다.

**③ 못 찾으면 조용히 넘어가지 않는다**
대상을 못 찾은 것은 "알림이 필요 없다"가 아니라 **"알림이 안 나간다"** 이다.
`alert_target()` 은 1:1 을 못 찾으면 부서 채널로 돌리고, 그 사실을 로그에 남긴다.
둘 다 없으면 `None` 을 돌려주고 **부르는 쪽이 로그를 남긴 뒤 건너뛴다.**

**④ 경로를 코드에 박지 않는다**
데이터 경로는 `lib.config.paths` 가 정본이다 — `paths.stage` · `paths.raw("mail")` ·
`paths.ledger` · `paths.weekly` · `paths.logs`. 형제 프로젝트 폴더(`projects/…`)를
가리키던 옛 경로는 **새로 설치한 기계에 존재하지 않는다.** 임포트는 통과하고
실행 시점에만 터지므로 게이트가 따로 잡는다.

## 5. 게이트가 잡는 것

| 규칙 | 무엇 |
|---|---|
| 개인 식별자 | 이름 · 계정 · 조직 고유명 (`scan.local.json`, 커밋하지 않는다) |
| 사용자ID 형태 | UUID 리터럴 |
| 폐지된 경로 | 패키징 이전의 형제-프로젝트 경로 (`projects/<옛 프로젝트명>/…`) |
| 비밀값 | 키 접두 · PEM · 토큰 리터럴 |

게이트는 **검사하지 않은 파일을 반드시 출력한다.** 바이너리(음성·이미지)는
구조적으로 볼 수 없으므로, 공개 전에 사람이 내용을 확인한다.
2026-10-16 에 9초짜리 시험 음성에 실명과 회의 내용이 들어 있었다.

## 6. 담당자가 바뀔 때

```bash
# 1. 설정에서 운영자만 바꾼다
vi config/harness.yaml            # operator.account

# 2. 캐시를 지운다 (옛 담당자의 ID가 남아 있다)
rm -f "$(python3 -c 'import sys;sys.path.insert(0,"core");from lib.config import paths;print(paths.state/"identity.json")')"

# 3. 확인
PYTHONPATH=core:agents:shared python3 core/lib/identity.py
```

코드는 한 줄도 고치지 않는다. **고칠 곳이 하나뿐인 것이 이 설계의 목적이다.**
