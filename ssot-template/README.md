# 정본 구조 템플릿

이 폴더를 조직의 공유 드라이브에 복사해 시작한다.

## 쓰는 법

1. `부서/` 를 실제 부서 이름으로 바꾼다 (예: `10_연구기획팀`)
2. `CLAUDE.md` · `AGENTS.md` 의 `<조직명>` 과 `<부서>` 를 채운다
3. `50_도구상자/00_규범/` 두 문서를 조직에 맞게 손본다
4. `.gitkeep` 파일은 지운다 (빈 폴더 유지용이었다)
5. 하네스 설정의 `ssot.dept_root` 에 부서 폴더 이름을 넣는다

## 왜 이 구조인가

| | |
|---|---|
| 과제를 생애주기로 나눈다 | 폴더를 옮기지 파일을 흩지 않는다. "지금 어느 단계인가"가 경로로 보인다 |
| 자동화 구역을 분리한다 | 사람과 기계가 같은 경로에 쓰면 충돌한다 |
| 온톨로지를 공통에 둔다 | 사람·조직 표기가 갈리면 문서마다 다른 이름이 생긴다 |
| 규범을 드라이브 안에 둔다 | 폴더를 여는 것만으로 규약이 전달된다. 별도 배포가 필요 없다 |
| `_시스템/` 을 기계 전용으로 | 색인·상태를 사람이 고치면 기계가 덮어쓴다 |
